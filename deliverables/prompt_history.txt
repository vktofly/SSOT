--------------------------------------------------
USER PROMPT 1: Data Reconciliation & Root Cause Analysis
--------------------------------------------------
Context: I have three datasets from a travel company (BharatTrip):
1. Support_Tracker (Refund requests taken by support).
2. Finance_Tracker (Payouts executed by finance).
3. Escalations (Client complaints regarding delayed/incorrect refunds).
4. Unstructured text (Informal WhatsApp/Email refund requests).

Task: Perform a strict data reconciliation to find the root cause of the rising refund escalations. Do not just subtract the total rows. 
Constraints:
- Use an ID-to-ID Database Join (Left Anti-Join and Inner Join) on the `Booking_ID`.
- Identify "Dropped Handoffs" (In Support, missing in Finance).
- Identify "Deduction Mismatches" (Present in both, but Support Refund Amount > Finance Payout Amount).
- Identify "Off-Tracker Leaks" (Cross-reference Escalations 'No Ref' with unstructured WhatsApp text).
Output the exact integer counts for each failure point and summarize the operational bottleneck.

--------------------------------------------------
USER PROMPT 2: Multi-Agent Architecture Design
--------------------------------------------------
Context: Based on the data analysis, the operational bottlenecks are WhatsApp leakage and manual sheet-to-sheet handoff drops.

Task: Design a system architecture for a Unified Single Source of Truth (SSOT) driven by LLM Agents.
Constraints:
- Must include an "AI Ingestion Agent" to parse messy unstructured text into structured JSON.
- Must include a "Reconciliation Agent" with a Human-In-The-Loop (HITL) approval UI.
- Must mitigate financial compliance risks and API key exposure (reference MCP - Model Context Protocol).
Format the output as a Markdown table mapping the "Operational Failure" to the "AI Engineering Solution".

USER PROMPT 3: Streamlit Prototype Development & LLM Routing
--------------------------------------------------
Role: You are a Senior AI Operations Engineer.
Task: Write a production-ready `app.py` using Streamlit to prototype the SSOT architecture we just designed.
Requirements:
- Build an Operations Telemetry Dashboard tracking "Active Escalations", "Missing Handoffs", and "Reconciliation Mismatches".
- Implement the AI Ingestion Agent using `google-genai` (gemini-3.5-flash). 
- Add hallucination mitigation: If the LLM hallucinates an invalid travel route (e.g. DEL to NYC instead of valid domestic routes), the UI must flag it.
- **Dynamic API Key Routing**: Build the app so it accepts BOTH an OpenAI API key (`sk-...`) or a Google Gemini API Key (`AIzaSy...`) via the Streamlit sidebar. If OpenAI is provided, fallback to the REST API without requiring the `openai` python package to keep dependencies ultra-lightweight.

--------------------------------------------------
USER PROMPT 4: Streamlit Cloud Deployment Optimization
--------------------------------------------------
Task: Create the necessary deployment files to host this Streamlit app on Streamlit Community Cloud.
Constraints:
- Write a `requirements.txt`. Do NOT strictly pin the versions (use `>=`) to prevent Debian C-compiler failures in the cloud environment.
- Create a `packages.txt` file including `zlib1g-dev` and `libjpeg-dev` to ensure Pillow and Pandas compile correctly if the cloud container defaults to a newer Python version without pre-built wheels.
- Create an industry-standard Python `.gitignore` that rigorously excludes `.venv`, `.env`, and `__pycache__` to ensure API keys never touch the public repo.
